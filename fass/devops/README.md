# DevOps流程

云计算项目的 DevOps 流程负责把代码、配置、凭据、构建计划、部署动作和发布证据串起来，确保每次云端变更都可复现、可追溯、可回退。

## 适用范围

- 适用于函数计算和 Serverless Framework 项目的构建、部署和发布。
- 适用于需要多环境区分的项目，例如 `dev`、`testing`、`master`。
- 适用于需要把腾讯云凭据、环境变量和云资源配置放进 CI/CD 流程的场景。

## 工作原则

- 凭据只放在受控平台，不写入仓库。
- 环境变量由 CI 注入，不在源码中硬编码。
- 部署前先检查配置和依赖，部署后要做访问验证。
- 每个环境都要有明确的资源名称、数据库、存储和网络配置。
- 失败时先回滚配置和版本，再处理根因。

## 工作链路

### 准备

- 确认 `serverless.yml` 可读取必要环境变量。
- 确认云函数目录和入口文件存在。
- 确认 `.env`、`*.env` 或 `.env.*` 不会进入 Git。

### 构建

- 安装 Python 依赖。
- 校验函数入口和依赖包。
- 生成或检查部署配置。

### 部署

- 由 CI 注入 `STAGE` 和云厂商凭据。
- 执行 Serverless Framework 部署。
- 记录部署结果和云函数版本。

### 验收

- 手动或自动触发函数。
- 查看函数日志和返回结果。
- 检查数据库、对象存储、文件存储等配套资源是否可用。

## 子页面

- Serverless Framework 部署函数计算
- 持续集成

## 快速检查

- CI 凭据是否授权到最小范围
- `STAGE` 是否和目标环境一致
- `.env` 是否只在运行期生成
- 云资源是否按项目和环境隔离
- 部署后是否留存日志和验收记录
