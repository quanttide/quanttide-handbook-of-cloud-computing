# 层管理

层管理负责把多个云函数共同使用的依赖、工具和运行时补充能力沉淀为可复用资源，减少重复打包和重复维护。

## 适用范围

- 多个云函数共同依赖同一批第三方包。
- 部分依赖较大，不适合每个函数单独打包。
- 工具函数、运行时补丁或公共配置需要统一维护。

## 工作原则

- 层只放稳定、通用、复用价值高的内容。
- 业务代码不放进层，避免隐藏依赖关系。
- 层版本要可追踪，变更要有说明。
- 更新层以后要验证所有使用该层的函数。

## 适合放入层的内容

- 常用第三方依赖
- 公共工具包
- 运行时扩展
- 体积较大但稳定的库

## 不适合放入层的内容

- 高频变化的业务逻辑
- 单个函数专用的配置
- 凭据、密钥和敏感信息
- 无法明确版本来源的文件

## 快速检查

- 层内容是否真正复用
- 层版本是否可追踪
- 依赖是否和运行时兼容
- 更新后是否验证受影响函数
